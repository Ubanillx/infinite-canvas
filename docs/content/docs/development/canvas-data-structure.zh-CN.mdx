# 画布数据结构

本文档说明画布数据在服务器与浏览器之间如何保存，以及节点结构、媒体文件和清理方式。

## 存储位置

权威数据在服务器，浏览器只保留可丢弃的缓存：

- 业务数据按数据域保存在服务器，接口为 `GET/PUT /api/data/:domain`，写入使用 revision 条件更新，冲突返回 409。数据域包括 `canvas`、`canvas-templates`、`assets`、`image-workbench`、`video-workbench`、`agent-sessions`。
- 浏览器用 zustand persist 在 `localForage`（库名 `infinite-canvas`，store `app_state`）写一份本地镜像，key 为 `workspace:<workspaceId>:infinite-canvas:canvas_store`（素材为 `asset_store`）。它只用于启动加速和断网展示，不是权威数据。
- 媒体对象通过 `PUT/GET/HEAD /api/media/blob/:storageKey` 读写，服务端映射到对象键 `media/<workspaceId>/<sha256(storageKey)>`，单文件上限 100 MiB。
- 媒体在浏览器按工作区缓存，store 名为 `workspace_<workspaceId>_image_files` / `_media_files`；缩略图另存 `_image_previews`（最长边 768px，只存在本地）。

画布 JSON 不保存大体积 base64。图片节点、视频节点、音频节点、助手附件和素材只保存展示 URL、`storageKey` 和元信息，真实字节通过 `storageKey` 读取。

旧版本地数据在进入工作区时迁移：`app_state` 里的 `canvas_store` / `asset_store` 复制到工作区命名空间，`image_files` / `media_files` 移到对应工作区 store 并上传服务器，迁移标记写入 `localStorage`，每个工作区只迁移一次。

## 画布项目结构

每个画布项目是一个 `CanvasProject`，文件夹是独立的 `CanvasFolder`：

```ts
type CanvasProject = {
  id: string;
  title: string;
  description?: string;
  folderId: string | null;
  createdAt: string;
  updatedAt: string;
  nodes: CanvasNodeData[];
  connections: CanvasConnection[];
  chatSessions: CanvasAssistantSession[];
  activeChatId: string | null;
  backgroundMode: "lines" | "dots" | "blank";
  showImageInfo: boolean;
  viewport: { x: number; y: number; k: number };
};

type CanvasFolder = {
  id: string;
  title: string;
  parentId: string | null;
  createdAt: string;
  updatedAt: string;
};
```

字段说明：

- `folderId`：所属文件夹，`null` 表示根目录；文件夹可嵌套，不允许把文件夹移入自身或后代。
- `description`：画布描述，画布库卡片会展示。
- `showImageInfo`：画布是否显示图片信息。
- `viewport`：视口变换，`x/y` 是屏幕平移，`k` 是缩放比例。
- 删除的画布会以 `CanvasDeletedProject`（`id` + `deletedAt`）记录删除标记，供快照导入时判断。

## 节点结构

每个节点是一个 `CanvasNodeData`：

```ts
type CanvasNodeData = {
  id: string;
  type: CanvasNodeTypeId;
  title: string;
  position: { x: number; y: number };
  width: number;
  height: number;
  metadata?: CanvasNodeMetadata;
};
```

`type` 是开放字符串：内置类型为 `image`、`text`、`config`、`video`、`audio`、`group`，插件节点使用 `<pluginId>:<name>`。

`metadata` 常用字段：

```ts
type CanvasNodeMetadata = {
  content?: string;
  composerContent?: string;
  prompt?: string;
  status?: "idle" | "success" | "loading" | "error";
  errorDetails?: string;
  fontSize?: number;
  generationMode?: "text" | "image" | "video" | "audio";
  generationType?: "generation" | "edit";
  model?: string;
  reasoningEffort?: "auto" | "low" | "medium" | "high" | "xhigh";
  size?: string;
  quality?: string;
  count?: number;
  texts?: CanvasNodeText[];
  primaryTextId?: string;
  images?: CanvasNodeImage[];
  primaryImageId?: string;
  inputOrder?: string[];
  references?: string[];
  naturalWidth?: number;
  naturalHeight?: number;
  freeResize?: boolean;
  storageKey?: string;
  mimeType?: string;
  bytes?: number;
  durationMs?: number;
  videoTaskId?: string;
  videoTaskProvider?: "openai" | "gemini" | "seedance" | "custom";
  groupId?: string;
  interactive?: boolean;
};
```

不同节点的使用方式：

- 图片节点：`content` 是当前可展示的图片 URL（通常是 `blob:` URL），`storageKey` 指向服务器媒体；`naturalWidth/naturalHeight/bytes/mimeType` 保存原图信息。
- 视频节点：`content` 是可播放地址，`storageKey` 指向媒体，`videoTaskId` / `videoTaskProvider` 用于刷新后继续查询远端任务。
- 音频节点：与视频节点共用 `storageKey` / `bytes` / `mimeType` / `durationMs`。
- 文本节点：`content` 保存文本；`fontSize` 保存字号；多文本生成时 `texts` 存全部备选，`primaryTextId` 指向主文本。
- 生成配置节点：`generationMode/model/size/count/inputOrder` 保存生成配置，上游输入通过 `connections` 计算。
- 组节点：通过 `groupId` 记录成员归属，组本身也是节点。
- 多图图片节点：批量生成仍是一个图片节点，请求开始前在 `images` 中创建全部槽位，每个槽位独立记录 `status/errorDetails`，最先成功的槽位立即成为 `primaryImageId`。展开状态只属于界面，不写入项目数据。

## 连线结构

```ts
type CanvasConnection = {
  id: string;
  fromNodeId: string;
  toNodeId: string;
};
```

连线只保存节点 ID，不保存端口坐标，渲染时按节点位置和尺寸计算路径。删除节点时会同步删除相关连线；删除组时按组内成员处理。

## 助手会话结构

```ts
type CanvasAssistantSession = {
  id: string;
  title: string;
  messages: CanvasAssistantMessage[];
  createdAt: string;
  updatedAt: string;
};

type CanvasAssistantMessage = {
  id: string;
  role: "user" | "assistant" | "system" | "tool" | "error";
  title?: string;
  text: string;
  meta?: string;
  detail?: unknown;
  references?: CanvasAssistantReference[];
};
```

`references` 里的引用图和附件同样遵循媒体规则：`storageKey` 存在时以它为准读取，需要 base64 时临时转成 data URL。

## 媒体写入与读取

新增图片走 `uploadImage(input)`：

1. 传入 `Blob`、data URL 或远程地址；远程地址只下载一次。
2. 解码校验为图片后生成 `storageKey`（`image:<id>`）。
3. 通过 `saveMediaBlob` 上传到 `/api/media/blob/:storageKey`，同时在本地缓存一份。
4. 返回 `{ url, storageKey, width, height, bytes, mimeType }`，`url` 为内存中的 object URL。

读取时 `resolveImageUrl` / `resolveMediaUrl` 先查内存 object URL，再查本地缓存，本地缺失会回源服务器并重新写入缓存。上传失败（例如超过 100 MiB）会直接报错，不会只保存在本机冒充成功。

## 清理机制

- 本地：删除节点或素材时移除对应本地缓存并 `URL.revokeObjectURL`，不影响服务器对象。
- 服务器：业务数据域写入时同事务替换该域的媒体引用清单（`media_references`），覆盖画布、模板、素材和生成记录。
- 垃圾回收目前只提供 owner 可调用的 `POST /api/media/gc/dry-run`：报告固定 `deletionEnabled: false`，候选也不会被删除。实际删除、保留期和调度尚未启用，详见[画布媒体引用与安全垃圾回收规划](/zh-CN/docs/progress/canvas-media-lifecycle-plan)。
