## Agent 消息排队与打断回复

- Codex 或 Pi 正在回复时，输入框不再禁用：继续输入并发送会把消息加入队列，输入区显示「N 条排队」，当前回复结束后自动按顺序发出下一条。排队期间再次发送会继续追加，队列长度可见。
- 当前回复运行中，「发送」按钮变为「加入队列」，旁边保留红色「停止」；输入框有内容时额外显示「打断并发送」，点击后立刻中断当前回复，等后端 turn 真正结束后跳过队列、优先发出这条新输入。
- 点击「停止」只中断当前回复并暂停自动排队，队列内容保留；之后手动发送一次即恢复自动排空，不会在刚停止后又自动发出下一条。
- 排队消息各自保留发送瞬间的文本、图片附件、文件附件、画布引用和 Skill，后续改动输入框或重新选择 Skill 不会污染已排队的消息；发送成功只清除该消息自己的 Skill 选中状态。
- 切换会话或新建会话时队列清空，避免上一个会话的消息发到新会话；排队期间刷新页面后队列不恢复，属于预期行为。
- 队列消息发送失败时，该消息内容回填到输入框而不是重新入队，避免自动重发形成循环；若输入框已有新草稿则保留新草稿，不覆盖。
- 打断后 10 秒内后端仍未结束回复时，日志记录「打断超时」，不会强行发送新消息，避免并发 turn 冲突。

## Agent 文件附件与产物导入

- 右侧 AI 助手可上传任意类型文件，不再只接受图片：文件在选中时即以原始字节流式上传到本机工作区的 `.infinite-canvas/files/<fileId>/`，输入区显示文件名、大小和上传百分比，上传未完成或失败时发送按钮不可用。图片仍走原来的 `localImage` 链路和缩略图预览。
- 单条消息最多 10 个文件附件、每个不超过 100 MB，单轮文件合计不超过 300 MiB；工作区文件总量上限 2 GiB，超限拒绝上传并提示清理。文件按会话绑定，删除会话会同步删除该会话文件；未发送的文件 24 小时后清理，已绑定文件保留 30 天。清理在 Agent 启动、删除会话和上传后最多每小时一次。
- 发送后可在 Codex 日志中确认提示词只包含本轮请求、图片附件清单和工作区文件绝对路径，不会把文件内容内联进提示词。要求 Codex「读取这份 PDF/表格并总结」时应真实读取该路径而不是凭文件名猜测。
- 让 Codex 生成结果并落到画布时使用 `canvas_import_artifact`：图片变成图片节点并保持原始比例，markdown、txt、csv、json 等文本类变成文本节点；PDF、压缩包等会被拒绝并返回原因。导入得到的节点可以继续连到生成配置节点生图。手动确认模式下该工具会先弹出确认卡片，拒绝后模型收到原因且不写画布。
- 本机文件附件只保存在工作区，不上传服务器媒体桶；刷新页面、切换会话或重启 Canvas Agent 后，历史消息里的文件附件仍显示文件名与大小，但换一台电脑或清空工作区后不可读取，需要重新上传。
- 引擎差异：Pi 模式不显示文件上传入口，也不接受带 `fileId` 的附件，提示切换到 Codex；图片附件在 Pi 模式下保持原有行为。
- 消息元数据存储升级到 v2，用于记录只有 `fileId` 而没有预览图地址的附件。首次启动会先把整个目录备份为 `message-metadata.v1-backup-<时间戳>` 再逐条升级；遇到损坏记录或未知版本时中止迁移并保留原文件，不静默覆盖。
- Agent 通信协议版本升到 8，旧版网页连接新版 Canvas Agent（或反之）会显示需要重启 Agent 的提示。

- 提示词编辑弹窗的标题、提示词和标签输入框不应再有单独的浅色底与固定边框，聚焦应与新建画布弹窗一致；生图和视频工作台的提示词框仍保留整块浅底色，悬停与聚焦只加深底色、不出现外扩阴影或高对比描边。

## 库页面

- 宽屏与窄屏、明暗主题下检查画布库、提示词库和资产库：标题与操作区对齐，搜索和筛选可用，卡片使用细边框且不出现大面积投影。画布库验证文件夹面包屑、拖放、重命名、导入导出、选择与删除；提示词库验证多标签筛选、无限滚动、详情、复制和加入资产；资产库验证筛选、分页、预览和全部卡片操作。空状态只展示真实数据。

## 生图工作台

- 点击「新建创作」和组装区按钮：整个点击过程保持扁平，不出现外扩阴影。检查 36px 参数与生成按钮、次要工具图标、禁用态和键盘焦点。提示词库与资产选择弹窗的响应式宽高应一致且不超出视口，内部列表自行滚动。两个搜索输入框悬停和聚焦只用轻微底色变化，不出现深色边框或阴影；资产搜索独占一行 40px 满宽并位于筛选之上。点击资产卡片应先预览原图，单独的「插入」按钮直接插入且不打开预览。检查图片、文本和视频卡片。
- 宽屏打开生图工作台，主内容和底部提示词应占满可用宽度，不出现居中的最大宽度留白。参考图区与结果区高度对齐且更高，底部提示词保持紧凑；参考图缩略图应更小，点击打开原图预览，重新排序和删除仍可用。提示词编辑器占满底部宽度，向上拖动其无边框上沿或用方向键调整可增高，使用轻微底色且无聚焦阴影；参数摘要、参数按钮和生成按钮位于同一行。
- 预览历史记录、切换生成结果、下载或保存图片、作为参考图、重新创作，以及带参考图和不带参考图各生成一次。检查抽屉打开与关闭、窄屏、键盘焦点、明暗主题和中英文。记录管理与生成设置都在右侧打开并在桌面端把工作台内容左推，打开一个应关闭另一个；设置抽屉直接显示全部图片设置，不再有二级展开。记录管理中检查选择、全选、删除确认和打开记录，卡片保留数量、成功/失败、耗时和时间信息。逐一检查两个抽屉、删除确认、提示词库与资产选择、模型列表、按钮、提示词与数字输入聚焦、参考图控件和选中设置：应使用主题细边框和轻微底色，无大面积投影或高对比描边。

## 视频工作台

- 检查紧凑历史条、图片/视频/音频参考与结果并排区域，以及底部提示词编辑器在宽屏和窄屏下的表现。宽屏时主内容和底部提示词占满可用宽度，不出现居中留白；编辑器可拖动上沿或用方向键增高，参数摘要与生成按钮同一行。三类参考都能添加、预览、排序和删除，上传、粘贴、资产选择和提示词库仍可用。
- 打开「管理记录」和「生成设置」：两者都出现在右侧抽屉，桌面端把工作台内容左推，切换时关闭另一个。设置应直接暴露通用模型和 Seedance 模型的全部选项，选中态用轻微底色和主题细边框，不出现大面积投影。检查明暗主题、中英文、键盘焦点、创作、待完成任务恢复、失败重试、成功播放、下载/保存到资产、记录选择与删除确认。

## 首页与顶部导航

- 画布右上角按钮应显示「AI助手」，阴影较轻；点击仍可打开或收起助手面板，浅色和深色主题下均清晰可见。

- 打开任意画布后，顶部左侧应有仅显示箭头图标的返回入口，悬停显示「返回画布库」提示；点击进入画布库，键盘可聚焦，明暗主题下都应清晰可见。

- 顶栏工作区切换入口应位于最右侧，显示当前工作区名称与下拉箭头；弹出面板应紧凑展示工作区、最近画布或数量，当前项以浅背景和对勾标识，不出现左侧竖线。检查切换、查看全部、新建、键盘操作、窄屏和明暗主题。

- 桌面与移动端的顶部导航不再显示 GitHub 和版本号；首页页脚显示可点击版本号，点击后仍能查看版本更新，其他页面不显示版本号。检查明暗主题和窄屏布局。

## 配置导航

- 从画布打开配置弹窗，依次切换渠道、偏好设置、提示词来源、WebDAV 和数据与存储：弹窗外框尺寸及位置应保持不变；长内容只在页签内容区滚动，页签和底部「完成」保持可见。可编辑页签的「保存配置」位于页签行右侧，数据与存储页不显示保存按钮；检查窄屏、明暗主题及键盘操作。

- 配置弹窗的页签内容应可用鼠标滚轮滚动到末尾（渠道内容较短时不滚动）；提示词来源页「全部立即拉取」按钮与上方拉取周期选择框、「尚未定时拉取」说明之间保持 16px / 12px 的纵向间距，不再贴边或压住说明文字，明暗主题一致。

- WebDAV 页应可填写地址、可选远程目录、用户名和密码；点击「保存配置」或离开密码输入框后应保存到应用服务器，刷新后显示地址、目录和用户名，密码只显示“已设置”而不回传原文。更改连接后立即测试、同步或读取快照，应先保存新配置并由服务端同源代理使用；保存失败不得以旧配置继续操作。检查无配置、错误地址、认证失败、中英文与明暗主题，快照仍只手动同步。

- 渠道、偏好设置、提示词来源和 WebDAV 在独立页面与快捷弹窗中应呈现新版分区布局；检查窄屏与宽屏、明暗主题、中英文和键盘焦点。原有编辑、保存、拉取、同步及快照导入操作仍应正常；WebDAV 同步与快照导入应分开展示，读取快照、选择快照和导入按钮之间应有一致的纵向间距。

- 桌面和移动端进入「配置」后，左侧菜单应分别显示渠道、偏好设置、提示词来源、WebDAV、数据与存储；直接访问 `/config` 和各个 `/config/<section>` 应显示对应内容，页面不再出现顶部页签。切换子菜单、刷新、浏览器前进/后退均应保持选中项与内容一致；桌面侧栏折叠时图标提示和选中态仍可使用。画布等页面唤起的快捷配置弹窗仍能打开指定页签，不改变当前页面地址；原配置说明及 JSON 导入、导出按钮应消失，配置编辑子页面和快捷配置弹窗应显示「保存配置」，「数据与存储」不显示该按钮。点击后向服务器保存当前配置，成功后提示，失败时显示错误并可重试；原有自动保存继续生效。

## 提示词来源

- 新配置的提示词来源列表应为空，仍可手动添加、编辑、删除和拉取自定义来源。已有服务器配置中的内置来源应被移除，自定义来源及其定时设置应保留；刷新后内置来源不再出现，提示词库不再展示其缓存内容，也不再发起其拉取请求。服务器保存清理后的配置失败时应显示启动错误，并可重试。

## 服务端数据与请求

- 媒体文件：在原浏览器工作区中进入应用后，旧 IndexedDB 图片、视频、音频应上传到服务器；另一浏览器访问同一工作区时应能看到并下载画布、资产和工作台记录引用的媒体。新上传媒体应直接保存到服务器；服务器不可用时应提示失败，不得只保存在本机冒充成功。单文件恰好 100 MiB（100 x 1024 x 1024 字节）应保存，多 1 字节即使采用分块传输或声明更大的 Content-Length 也应返回 HTTP 413，明确提示未保存到服务器，不留下临时文件或成功记录，并可换较小文件重试；旧数据迁移超限时保留 IndexedDB 原件，之后进入工作区仍可重试。WebDAV 仍仅手动创建或导入快照。
- 工作区数据：画布、资产与生图/视频记录应以服务器版本为准；首次仅有本地数据时先上传再使用。服务器读取失败应阻止把空白数据当作工作区继续编辑；写入失败应持续提示并可重试，版本冲突不应覆盖他人数据。
- 数据与存储：当前工作区的服务器统计应显示画布、素材、生图/视频记录、Agent 会话和媒体文件的实际内容体积，切换工作区后只显示新工作区的数据；浏览器数据应按提示词、图片预览、当前工作区副本和其他历史数据汇总，默认不铺满技术仓库名，展开后仍能查看各仓库。刷新应分别更新两处数据；任一处读取失败时另一处仍可显示。画布与素材编辑成功写入服务器后，不应继续新建本地业务副本；首次仅有本地旧数据时仍应先迁入服务器。异步写入过程中切换工作区，不得把旧工作区内容写入新工作区。
- 请求路径：提示词来源应由服务器获取并拒绝私有地址、非 HTTPS 或重定向；远程媒体下载应走同源代理，公网 HTTPS 正常、内网和 HTTP 地址明确失败；配置页不再显示本地代理入口。自定义模型脚本、浏览器直接渲染的外链媒体和 Agent 请求还需另行核对，不能据此宣称全部外部请求已服务端化。

## 首页

- 首页仅显示新版节点连接主视觉，不再展示提示词卡片或提示词加载错误。两个画布入口仍可使用；检查中英文、桌面与手机、明暗主题、键盘焦点以及减少动态效果设置。
- 图片节点的 SVG 应显示玻璃球体、前后遮挡轨道、细线与柔和光影；缩小后不裁切，明暗主题下卡片边缘与阴影自然。
- 首页应移除英文装饰标注、编号、坐标及 SVG 内小字，显示新版主副文案。移动鼠标时，背景丝线局部弯曲、光晕与节点平滑跟随；离开后回到默认位置。检查明暗主题、手机触控、页面缩放、后台标签页暂停、离开首页后停止动画，以及系统减少动态效果开关即时生效。

## 开发调试工具

- `npm run dev:smoke` 应在几秒内全部通过，覆盖工作区列表、工作区创建、无工作区头 403、数据写入/读取/版本冲突 409、工作区隔离，以及 `/`、`/canvas`、`/assets`、`/image`、`/video`、`/prompts` 的页面外壳；产物在 `.local/smoke-*/`，失败时退出码为 1。
- `npm run dev:probe -- --url http://127.0.0.1:3000` 复用已启动的开发服务器时不应新起进程；浏览器无控制台错误、无未捕获异常、无失败请求和 4xx/5xx 响应时通过，并生成截图与 `report.json`。首次进入工作区选择页的截图应与实际页面一致。
- `npm run dev:browse -- <url> --step ... --shot ...` 能按顺序执行步骤，失败时自动截图；`npm run dev:shot -- <url> --theme dark` 能按指定视口和主题取图。
- `npm run logs` 对没有错误的日志返回 0，对包含 `error` 等关键字的日志返回 1；`--list` 和 `--tail` 分别列出和跟踪日志。
- `npm run dev:server` 退出时打印日志扫描结果；`npm run doctor`、`npm test` 和 `npm run test:e2e` 的行为保持不变。
- 桌面与移动端 E2E 应能在本地创建工作区并进入同一画布、刷新后仍在同一工作区，且不同工作区之间无法读取对方数据；运行数据只写 `.local/e2e-*/`，不修改普通开发数据。
- 人为制造浏览器控制台错误或失败接口时，E2E 应失败并附带浏览器诊断、trace、截图和本地服务日志；`npm run logs:check` 应报告服务端错误并以非零码退出，`npm run test:report` 能打开生成的 HTML 报告。

## 内部代码清理回归

- 画布内图片、视频、音频和文本设置弹层仍应在按钮上方或下方展开，不超出视口，并随页面滚动和窗口缩放重新定位；点击弹层外部仍会关闭。文本弹层高度，以及图片弹层关闭时让输入框失焦的行为应保持不变。
- 生图、音频和文本设置的选项样式与选中行为保持一致，视频与音频设置分组布局不变；图片和视频参考图排序的边界按钮与排序结果保持一致。
- 画布提示词输入框与配置编辑器的光标定位、`@` 插入行为保持一致，参考缩略图、引用标记序列化和换行结果不变。
- 图片、视频和音频 API 保留各自原有的错误文案，包括 JSON/HTML 错误解析、取消请求，以及各自的 HTTP、网络和超时处理；视频与模型脚本轮询的取消行为不变。
- 视频与模型脚本复用同一个取消信号持续轮询时，每次等待结束应释放对应的取消监听器；提前取消或等待中取消仍返回 `AbortError`，轮询间隔与超时不变。

## 白玉浅色主题

- 切换白天模式后，首页、顶栏、侧栏、画布库、工作区弹层、生图工作台和视频创作台应使用接近白色的白玉中性色；不应出现玉绿色品牌色或明显的米黄色大块背景。
- 卡片和浮层使用极轻阴影，边界清楚但不厚重；文字、按钮、选中态和 Ant Design 弹层在浅色背景上保持清晰对比。深色模式应保持原有暖炭黑方向。

## 全局加载体验

- 已选工作区分别在首页、画布库、画布编辑页和资产页刷新，确认全屏轨道动画从开始覆盖工作区与配置加载，当前页面和数据准备好后才渐出；不能短暂出现「选择工作区」、局部转圈或未恢复完成的画布。检查深浅主题和系统减少动态效果设置。
- 未选工作区时，动画结束后显示工作区选择页；已选工作区若在服务器上不存在，校验后显示选择页。切换、创建工作区和配置加载失败后重试时也应使用同一动画，并在失败时显示可操作的错误信息。

## 顶栏工作区切换

- 顶栏清楚显示当前工作区名称，长名称和窄屏不挤压其他操作；点击后在顶栏下方打开无图标、黑白灰配色的切换面板，当前项以浅灰底、细标记和「当前」文字区分。工作区数量及最近画布只显示服务器实际返回的数据，刷新列表失败时说明正在显示缓存项。
- 选择其他工作区后页面重新载入并显示对应数据；点击「查看全部工作区」进入全屏选择页，点击「新建工作区」直接进入创建页。两个底部操作在明暗主题下应等高、使用中性色及清晰的 14px 文字，悬停和焦点反馈可见，深色模式不出现突兀的空白色块；键盘能打开、遍历及按 Escape 关闭面板，Agent 面板打开时位置、焦点与内容不被遮挡。

## 新建画布

- 从画布库按钮、空状态按钮和编辑器菜单新建画布时，必须先输入非空名称，描述可以留空；取消后画布数量不变。填写的描述应在画布卡片显示，未填写时显示“暂无描述”；刷新、导出导入和切换工作区后仍应保留描述。
- 打开 `/canvas?mode=new` 时先填写名称和选填描述，取消后回到画布选择；`/canvas?mode=recent` 没有画布时也应显示同一创建表单。

## 功能导航侧栏

- 桌面端检查创作、资源、设置三个分组和六个入口；切换路由后高亮跟随当前页面，画布编辑页仍不显示全站导航。侧栏折叠后仅显示居中的图标、悬停提示与当前页标识，图标悬停有轻微动效；展开与折叠过渡顺畅，刷新后状态保留，键盘可操作且系统减少动态效果时无多余动画。
- 手机和平板端通过顶栏菜单打开分组抽屉，导航后自动关闭；工作区切换、Agent、语言、主题等入口不被挤出屏幕。右侧 Agent 面板打开且窗口较窄时，侧栏改用抽屉入口，关闭面板后恢复原折叠状态。明暗主题、英文界面及右侧 Agent 面板打开时，侧栏和画布列表均不应遮挡或横向溢出；画布库标题、操作区和空状态与设计稿一致。

## deploy 合并回归

- 新建嵌套画布文件夹、拖拽移动画布/文件夹、重命名后刷新并切换工作区，确认层级与数据持久化且工作区之间隔离；不得将文件夹移入自身或后代。
- 进入嵌套文件夹时地址栏应出现 `folder` 参数；刷新、浏览器前进后退及直接打开该地址仍在对应文件夹。返回根目录后参数消失；删除当前文件夹或打开无效文件夹地址时回到有效目录。从文件夹中的画布点击顶部「返回画布库」后，应回到该画布所属文件夹。
- 删除含画布的文件夹，手动上传 WebDAV 快照后导入旧快照，已删除画布不得复活；导入保留文件夹层级和本机文件夹修改，不含文件夹的快照不得清空本机文件夹。
- WebDAV 继续采用手动快照且禁止自动写入；首次上传只探测共享边界目录，不枚举其他工作区，越权路径仍拒绝。

## 工作区选择与进入

## Canvas Codex Agent 一键启动

- 执行 `./run-all-background.sh` 后，Web 与 Canvas Agent 均启动并通过健康检查。
- 浏览器打开脚本输出的 `http://<局域网地址>:3100` 后自动连接 Agent，无需填写或查看真实连接 token。
- Agent 仅监听 `127.0.0.1:17371`，局域网请求统一通过 `/api/canvas-agent` 同源代理。
- `./run-all-background.sh status|restart|stop` 能正确查询、重启和停止两个服务。

- 已保存模型失效：画布节点已选模型后，移除所属渠道或该模型，并保留另一个默认视频模型。生成、重试及未完成视频恢复应保留失效模型选择并打开配置，不能向默认模型或第一个渠道发送请求；明确重新选择有效模型后才可生成。同渠道仅换 API Key 应保留原模型；配置节点从有效图片模型切换到视频类型时仍应使用视频默认模型。

- 画布图片预览：画布图片节点、左侧元素列表、节点参考栏、我的资产卡片、资产选择弹窗、生图工作台的结果卡片与历史缩略图、生图和视频工作台的参考图都使用最大边长 768px 的缩略图渲染，使图片较多时不再反复解码原图。缩略图只存在本地，画布数据、资产数据、生图历史、导出包和 WebDAV 同步里都不应出现缩略图内容，删除图片或用不到时也应一并清掉。点开大图、编辑、下载、导出和生成参考图必须继续使用原始图片；图片本身不超过 768px、只有远端地址（跨域读不到本地内容）、或使用自定义封面时应回退原图。
- 画布拖拽与连线渲染性能：单选、多选、拖动整组节点时位置跟手，松手后落点与拖动过程一致；把节点拖到组上方时组高亮出现和消失的时机正常，松手能正确加入组，拖出组也能正确移出；组节点自身被拖动时不应出现组高亮。画布缩放和平移到只显示局部时，视口内的连线应完整显示（包含两端节点都在视口外、但曲线穿过视口的连线），连线的点击选中和右键菜单仍可用，连线拖拽创建过程中的虚线跟随正常。
- 本地代理：独立页签、默认关闭、地址规范化、复制启动命令和连接测试均应正常；开启后仅浏览器直连及远端媒体请求经本机代理，服务端托管 AI 与 WebDAV 始终使用带认证的同源代理。关闭后直连恢复，SSE 不缓冲，data/blob URL 不改写，代理开关不得泄露服务器密钥或绕过工作区权限。
- 图像与视频尺寸设置：图像设置应将分辨率（`1k` / `2k` / `4k` / 自动）和宽高比（`1:1`、`2:3`、`3:2`、`4:3`、`3:4`、`16:9`、`9:16`、`21:9`、`9:21`、自动）拆成两项，并由二者计算 W/H。视频设置仍使用 `480p` / `720p` / `1080p`（以及自定义 p 值），比例为 `1:1`、`3:4`、`4:3`、`16:9`、`9:16`、`21:9`、自动，并由清晰度与比例计算 W/H。秒数应为 4–30 的滑杆，右侧显示当前秒数；比例为自动时应禁用 W/H。 此处 4–30 秒仅用于通用视频渠道；方舟/Seedance 保留专用面板与 -1 自动、4–15 秒、参考视频和音频校验。
- 视频内置请求：未配置调用脚本时，OpenAI 格式应按模板发送 `mode`、`first_frame`/`last_frame` 或 `image[]`、`generate_audio`、`watermark` 以及参考视频/音频，不再使用 `input_reference[]`；Gemini 格式应走 `predictLongRunning`，按模式发送 `image`/`lastFrame` 或 `referenceImages`，不再提示不支持视频。刷新后应能继续查询 Gemini 任务状态。
- 视频生成模式：视频设置应出现「首尾帧」和「全能参考」；1 张图按首帧、2 张图按首尾帧发送专门字段，超过 2 张即使选了首尾帧也按全能参考发送。内置请求和调用脚本的 `params.mode` 均为 `frames` 或 `reference`。
- Gemini 生图：Gemini 格式渠道和 Gemini 生图调用脚本应使用 `generationConfig.responseModalities: ["TEXT", "IMAGE"]`，比例和尺寸放在 `imageConfig.aspectRatio` / `imageConfig.imageSize`，不再发送 `responseFormat`。
- 视频调用脚本：能力为「视频」的模型打开「调用脚本」后应进入全屏分步配置；左侧按「看懂规则 → 让外部 AI 写 → 可用变量」展示，可用变量应包含 `videos`（参考视频 File 数组）和 `audios`（参考音频 File 数组）；「复制写脚本说明」应包含当前能力、可用变量、返回要求和写法约束。插入的模板应是带参数列表的 async function，并把 `params` 拆开；OpenAI 生图模板必须包含 `quality`、`size`、`count`、`background`。OpenAI 视频模板应使用 FormData，带上 `mode`、时长、尺寸、分辨率、配音、水印以及参考图/视频/音频；`mode=frames` 时应使用 `first_frame` / `last_frame`，`mode=reference` 时应使用 `image[]`，完成后轮询并下载 `/content`。把外部 AI 写好的脚本粘贴到右侧并保存后，画布连接参考视频或参考音频再生成时，脚本应能读取这些文件。
- URL 凭据导入：使用新的有效 `baseUrl` 和 `apiKey` 打开应用时，应新增独立渠道且不修改已有渠道；再次导入相同 Base URL（含末尾斜杠或 `/v1`）时只更新对应渠道并保持幂等；仅提供 API Key 或提供非法 Base URL 时，所有配置都应保持不变。

- Canvas Agent 生成流程引用：提示词仅包含已经通过 `referenceNodeIds` 传入的 `@[node:...]` 引用时，应直接把现有文本、图片、视频、音频或组节点连接到生成配置节点，不再创建重复的提示词文本节点；提示词包含普通文字时仍应创建独立的提示词文本节点。

- 组节点引用：组节点应使用透明、轻量的边框与标题样式，并显示右侧输出连接点；把组连接到生成节点后，组内有内容的图片、视频、音频、文本及可引用扩展节点都应作为输入，普通提示词面板的 `@` 列表应显示组内资源，生成配置的 `@` 列表应允许一次选择整组；组与单节点重复引用时不得重复发送同一资源。
- 多选打组：框选或点选至少两个节点后，应出现包住全部选中节点的圆角虚线框，框上方显示「打组」；点击后用组节点包住这些内容并保持原位置，随后选中该组。选中组后可通过顶部「解散组」、右键菜单或 `Ctrl/Cmd+Shift+G` 取消分组；已同属一组的节点再次多选时应显示「解散组」而不是再打一组。拖入组、组引用和左侧树形列表应继续可用。
- 节点参考栏：普通节点提示词面板、放大编辑器和生成配置输入框上方应显示当前输入节点；图片和视频显示缩略图并可悬停预览，文本、音频及扩展节点显示对应类型；组连接应展开显示组内每个有效内容节点，删除任一展开项都应断开整组连线。点击加号进入画布选择后可连续添加有效参考，已连接、目标自身、已通过组引用的组内节点及不可引用节点不可重复选择，按 ESC 或顶部提示返回输入框；新增连接后 `@` 列表应立即更新。
- 多图透明背景：展开包含透明 PNG 或 WebP 的多图节点时，主图与所有备选图的透明区域都应直接显示画布背景；切换主图前后不得出现白色或主题面板底色。
- 画布选择与平移：左下工具栏应能切换「选择」与「移动」模式并用图标显示当前模式；选择模式拖动空白区域应显示疏朗清晰的虚线框，虚线长度、间距和粗细在任意缩放比例下保持一致；移动模式应能从空白区域或节点上拖动画布。按住 Control 或空格应临时反转当前工具且不改变工具栏模式，即选择变移动、移动变范围选择；点击画布页任意按钮后按空格应只临时切换工具，不得再次触发该按钮；输入框和可编辑文本内仍可正常输入空格。中键平移以及 Shift/Cmd 追加选择节点应继续可用。

- Agent 动态工具信息：执行内置生图、查看图片、命令、文件修改或其他动态工具时，卡片标题应显示具体工具名称；执行失败时正文应显示真实错误原因，刷新并恢复历史对话后仍应保持一致，不再统一显示「工具操作已完成」。

- Agent 顶部栏：在对话、历史和日志之间新增「技能」标签并显示已加载数量；连接状态应位于左侧 Agent 标题旁，并与右侧新对话使用相同规格的文字按钮，只有内容标签显示选中线；标签图标始终显示，中英文模式下都应按标签区域的实际可用宽度隐藏文字并保留小号数量，空间足够时显示图标和文字，拖动宽度时不应裁切、换行、横向滚动或错位。
- Agent 输入框窄屏布局：底部上传、Skill、确认模式、权限模式、模型和思考程度控件在窄面板下应只显示图标，宽面板下恢复文字；所有纯图标操作悬停时应使用统一样式显示名称或当前状态，任意宽度都不出现横向溢出。
- Agent 本地 Skill 管理：连接 Canvas Agent 后进入「技能」，应能读取当前 Codex 工作空间发现的项目、个人、系统和管理员 Skill，并支持搜索、按范围筛选、刷新及启停；未能加载的 Skill 应通过可点击、可滚动的详情查看原因；画布在站点工作空间 `.agents/skills` 下创建的 Skill 应可新建、编辑和删除，其他来源只读且不得被画布改写；编辑期间文件被其他窗口修改时应拒绝覆盖，清空显示名称、短说明和默认提示词后旧值应被删除，同时保留图标、品牌色等未由当前界面管理的元数据；多个标签页同时连接时，任一页面的 Skill 变更应自动同步，断开或切换 Agent 时旧请求不得重新写回列表或弹出编辑器。
- Agent Skill 草稿生成：创建 Skill 时应提供「空白创建」「从当前对话生成草稿」「从当前画布生成草稿」三种入口；空对话不得发起生成，取消时不得写入文件，确认后才写入站点工作空间 `.agents/skills`；Agent 运行中应禁用生成，多标签页下对话和画布来源必须分别严格绑定发起请求的 `threadId` 和 `clientId`，生成期间外部 MCP 仍应操作最近聚焦页面；草稿运行时创建、启停、删除和更新 Skill 应被统一拒绝，点击停止应真实中断临时草稿 turn；草稿不得泄露本地路径、密钥、媒体数据、真实节点 ID 或任务进度等临时状态，普通中文斜杠文本与 `/imagine` 等命令必须保持完整，生成草稿使用的临时 turn 不得出现在 Agent 对话、历史或日志中。
- Agent Skill 调用：在技能页点击「使用」或在输入框输入 `/` 搜索并选择 Skill 后，Skill 应作为原子 token 插入正文，而不是显示在输入框上方；发送任务时应通过 Codex 原生结构化 Skill 输入执行，发送成功后清除选择，失败时保留；新建对话、断开连接、Skill 被停用或删除时也应清除失效选择，发送前、任务完成后和刷新历史后的用户消息文字与 token 位置应保持一致。
- Agent 输入框快捷引用：输入 `/` 后应显示已启用 Skill 列表，输入 `@` 后应显示当前画布的图片、视频、音频和文本素材，长列表使用较高的内部滚动区域；选中项应按当前光标位置插入正文，例如「这是第一张图 `@图片1` 融合第二张图 `@图片2`」，不再集中显示在输入框上方，按 `Backspace` 或 `Delete` 时应整块删除；发送时应保持原句顺序，按节点 ID 精确引用发起页面的素材，并把引用图片的实际内容交给 Codex；输入框和聊天记录都应将引用渲染为与正文基线对齐的紧凑标签，悬浮或聚焦后可预览图片、视频、音频或文本内容，不重复显示内部图片附件，切换会话或刷新后引用样式应保持；可用方向键、`Enter` 或 `Tab` 选择，`Esc` 应关闭候选菜单，候选菜单打开时回车不得误发送消息。
- Agent 消息元数据：发送包含图片附件、Skill 或画布引用的消息后，刷新当前页面、在另一页面恢复同一对话或重启 Canvas Agent，历史消息都应由 Agent 按准确的 `clientMessageId`、`threadId` 和 `turnId` 恢复展示，本地缩略图仍可悬浮或点击查看，不依赖浏览器 IndexedDB 或文本匹配；通信协议版本变化不得清空独立的消息存储，遇到未知版本或损坏清单时应拒绝写入且保留原文件；删除线程后对应缩略图和引用元数据应同时删除，不得按记录数量或文件大小静默裁剪，改动前仅存在于浏览器旧缓存中的消息继续显示普通文本且不尝试迁移。
- Agent Markdown 样式：右侧 Agent 回复中的代码块应为横向占满消息区域、无语言标题和无双层边框的紧凑代码条，单行内容不应保留纵向大面积空白，复制操作仅在悬停时弱化显示；行内代码、链接在浅色和深色主题下应清晰；点击外部链接后应显示中文紧凑确认弹窗，长路径能够正常换行且复制、继续打开和关闭操作可用；点击 `/Users/`、`/home/` 等本地绝对文件路径时应改为提示在系统文件管理器中定位，支持复制路径，且浏览器地址不应跳转为 localhost 文件路径。
- Agent 工具确认模式：右侧面板标题栏不应再显示「工具确认」开关；对话输入框左下方应显示确认模式选择，默认选中「自动确认」，画布写入工具应直接执行；切换为「手动确认」后，画布写入工具应在对话中展示等待确认卡片，并支持批准或拒绝。
- Canvas Agent Codex 升级：启动 Canvas Agent 后应输出 Canvas Agent、内置 Codex 和本机 Codex 版本，实际运行的内置 Codex 应为 0.164.0；内置与本机版本不一致、未安装本机 Codex，或 npm 存在更新版本时应显示对应升级提醒，npm 检查失败不应阻止服务启动；Agent 应能正常连接 Codex、创建或恢复会话、发送消息并调用画布工具，运行中停止任务应只中断当前 turn，随后无需重启 Agent 即可继续发送新任务。
- Canvas Agent Debug：普通启动应通过公共 logger 输出 Info、Warn 和 Error 日志；使用 `npx -y @basketikun/canvas-agent@latest --debug` 启动后还应输出 Debug 日志并显示日志文件路径，终端统一采用“`YYYY-MM-DD HH:mm:ss` 级别 消息 详情”的纯文本单行格式，`~/.infinite-canvas/logs/` 下应按启动日期生成相同格式的 `canvas-agent-YYYY-MM-DD.log`，同一天多次启动应追加到同一文件；日志中不应出现连接 token 或图片 Data URL 原文。
- Canvas Agent 凭据脱敏：Codex 与 Claude CLI 的 stderr 包含 Bearer token、`sk-` 密钥、显式 API key/token/authorization 赋值、ANSI 样式或跨输出分片的凭据时，调试日志和网页诊断事件均不应出现明文；普通 stderr 文本应保持不变。
- Canvas Agent 配置权限：在 Linux 和 macOS 上保存配置后，`~/.infinite-canvas` 权限应为 `0700`，`canvas-agent.json` 权限应为 `0600`，已有的宽松权限也应被纠正；配置应能继续正常读写，Windows 启动不受影响。
- Canvas Agent URL 自动连接：链接应在 `#` 后传递 `agentUrl` 和 `agentToken`，进入或选择具体画布时继续保留，读取后立即从地址栏移除，并可连接有效的本机、局域网或远程 HTTP(S) Agent 地址且不主动展开设置面板；缺少参数或地址无效时应展开设置并显示错误。
- 图片 API 模型参数：`gpt-image-*` 的生成和编辑请求不应发送 `response_format`，`dall-e-*` 请求仍应发送 `response_format: "b64_json"`。
- 图片外链持久化：画布和生图工作台对图片接口返回的远程 URL 应只下载一次，经图片解码校验后保存为工作区媒体（服务器对象存储 + 浏览器缓存）；返回 `200` 但内容不是图片时应失败，下载期间停止画布生成后不得保存或应用结果；浏览器因 CORS 无法读取但图片仍可显示时，应保留原 URL 且不生成空 `storageKey`，插件调用在外链可读取时仍应收到 Data URL。
- 多参考图编辑：OpenAI 格式在多张参考图时应使用重复的 `image[]` 表单字段提交文件，单张参考图仍使用 `image`；新建的 OpenAI 图片脚本应使用相同字段名。Gemini 渠道和已经保存的自定义脚本不受影响。
- Canvas Agent Codex 日志：Codex app-server 输出带颜色或样式控制符及 UTC 时间的 stderr 时，本地日志和网页诊断日志应只显示一份 `YYYY-MM-DD HH:mm:ss` 本地时间和干净文本，不应出现重复 ISO 时间或 `[2m`、`[31m` 等 ANSI 转义内容。
- Agent HTTP 诊断日志：网页发送一条普通消息后，本地 Debug 日志不应重复输出 `/health`、`/canvas/state`、`/canvas/activate` 成功请求、流式增量或完整会话响应，只保留 HTTP 请求与 Codex 生命周期摘要；右侧「日志」应以单行时间线展示发送、开始、回复、工具、完成用量和错误，不再输出 userMessage started/completed、流式摘要、重复 threadId 或大段原始 JSON。
- Agent 排查日志：右侧「日志」中的排查视图应显示连接摘要，并可按错误、警告和信息筛选；向下查看日志时仅列表内部滚动，标题、连接状态、筛选数量和操作按钮保持固定；连续相同事件应折叠计数，单条日志可展开查看完整详情；原始 JSON、复制全部、复制最近错误和清空功能应继续可用，浅色与深色主题下均应清晰。
- Agent 排查日志顺序与跟随：日志应按时间从旧到新排列，进入日志或切换筛选时定位到最新事件；停留底部时自动跟随新日志，展开最后一条后应继续停留在完整详情底部，向上浏览后暂停跟随并显示与对话区视觉高度一致的居中圆形向下箭头，新日志数量只在悬浮提示中显示；列表底部不应出现额外留白，点击按钮后回到底部并恢复跟随。
- Agent 对话统计：用户消息应右对齐并使用透明无气泡的简洁排版，用户和 Codex 两侧均不显示人物头像，消息下方均不显示时间或 Token 信息；输入框上方应居中展示最新一次模型调用的输入、缓存、输出 Token 用量，不显示会话累计值，数值更新时应从旧值平滑滚动到新值而非突然跳变，新建、切换或删除当前会话后应清空旧统计。
- Agent 回复实时显示：在右侧 Agent 发送消息后，用户消息下方应立即出现“正在思考...”，任务运行期间不应闪退；工具完成后应显示 Codex 正在继续处理及已等待时长，等待超过 30 秒时提示可继续等待或停止本轮；Codex 的回复应在当前对话中持续显示，实时事件缺失时也应在任务完成后自动同步完整内容，无需切换到历史或日志再返回对话。模型繁忙等任务失败时应立即结束等待状态，在对话中显示中文错误原因和重试建议，诊断日志不应再把失败轮次记为“处理完成”，刷新历史后错误仍应保留。新建尚未发送首条消息的空会话不应反复出现历史读取失败。
- Agent 对话实时与历史一致性：运行包含思考、命令及画布工具的较长任务，在执行中刷新发起页面或打开第二个页面时，已出现的用户消息、思考过程、工具卡和回复前缀均应保留并继续更新；同一思考或工具只显示一张卡片，任务结束及再次刷新后内容、顺序和状态应一致。切换页面焦点不能改变本轮画布工具目标，发起页面断开后不得把图片或写操作转交其他画布，使用相同页面身份重连后才能继续处理。
- Agent 流式交互性能：发送长回复时文字应连续平滑出现，输入框、滚动和画布操作不应随回复变长而明显卡顿；长历史会话中只有当前流式消息持续更新，屏幕外消息不应造成明显布局压力；任务完成后应通过 SSE 自动同步完整历史，不再持续请求 `/health` 轮询状态。
- Agent 过程时间线：新建 Agent 对话后 Codex 应生成可读思考摘要，并在运行时依次显示中文的思考摘要、执行计划、命令执行、网页搜索、文件修改和画布工具活动；思考摘要的图标、标题和箭头应稳定保持在同一行，默认收起且无边框，点击箭头后才展开 Codex 实际返回的具体摘要，其中 Markdown 强调、列表和代码应正确渲染而非显示原始符号，多行代码块和文本流程图应保留原始换行并允许横向滚动，完成事件不应再用「已完成分析」覆盖已经收到的摘要；同一轮连续命令应合并为显示数量的无边框折叠行，折叠时不显示命令预览，单条展开后直接显示详情，多条展开后可逐条查看工作目录、耗时、退出状态和运行输出；其他工具调用继续使用紧凑卡片排版，状态图标、标题和状态文字保持在同一行；结构化任务进度不应混在对话时间线中，而应独立放在对话区下方、Token 统计上方，支持展开和折叠，并逐项实时更新「待处理」「进行中」「已完成」状态；新任务生成时默认展开，任务结束后保留最新结果，同一计划更新不应生成重复内容；文件详情展示文件路径与新增/修改/删除动作，工具详情不应出现请求 ID、英文工具名或原始 JSON；一轮对话结束自动同步历史以及刷新页面后从历史中 resume 对话时，思考摘要、命令和工具过程记录仍应完整保留并保持相同展示。
- Agent 权限控制：输入框可选择「请求批准」「自动审查」「完全访问」；请求批准模式下，Codex 编辑工作区外文件、执行受限命令或访问网络时应在对话中显示审批卡片，支持拒绝、允许一次和本会话允许，并能依次处理多个并发请求；提交决定后卡片应保持禁用等待，只有 Codex 确认处理后才移除；等待审批时刷新页面，未处理的审批卡应自动恢复且不能让任务永久卡住；自动审查模式应仅将需要用户决定的风险操作送入审批；完全访问必须先显示风险确认，启用后可访问网络和本机文件且不再请求审批；选择应在刷新后保留。
- Agent 历史记录：点击记录卡片应直接进入对应对话，不再显示「进入」按钮；可勾选单条或全选多条记录并批量删除，删除当前对话后聊天内容应清空。
- Agent 默认新对话：每次进入任一画布并连接 Agent 后，对话区应保持空白且不自动恢复上一次会话，并在后台创建新线程、预热 MCP；需要继续旧对话时可在「历史」中主动选择恢复。
- Agent 当前画布优先：在已打开某个画布时要求 Agent 创建、修改、整理或生成内容，Agent 应直接读取并操作当前画布，不应先调用 `canvas_list_projects` 或使用 `site_navigate` 重复进入画布；只有明确要求查看或切换其他画布时才允许查询画布列表并导航。
- Agent 图片消息：发送一张或多张图片附件后，图片应紧跟用户文字并在消息右侧显示为约 40px 的紧凑缩略图，不再撑大消息区域，单击缩略图应打开大图预览，打开或关闭预览不应改变消息间距或产生额外空行；任务运行中、完成同步历史、切换页面及重新进入历史对话后都应显示浏览器本地保存的图片缩略图，不应消失或把 attachmentId、附件使用说明等内部上下文回显到用户消息中；删除历史会话后应同步清理对应缩略图。
- 画布文本复制：在 Agent 对话或节点信息详情中用鼠标选中文字后，按 `Ctrl/Cmd + C` 应复制所选文本，不应触发画布节点复制；未选中文字且焦点位于画布时，原有节点复制快捷键应保持可用。
- Agent 工作目录指令：`canvas-agent/agent-instructions.md` 应作为独立维护源；重启 Canvas Agent 后，当前工作目录应自动生成 `AGENTS.md`；新建对话发送消息时，Codex 日志中的用户消息只包含本轮请求和必要的附件上下文，不再重复整段 Infinite Canvas 前置提示词，画布及工作台工具仍可正常调用。
- 画布文本设置：文本节点和生成配置节点切换到文本模式后应显示推理强度设置，可选择自动、低、中、高、极高；选择自动时默认 OpenAI Responses 请求不应携带 `reasoning`，选择其他档位时应携带所选强度，刷新画布后节点设置应保留；文本模型自定义调用脚本应能读取 `reasoningEffort`，OpenAI 模板应按自动或指定档位正确组装请求。
- 生图工作台参考图：将一张或多张图片拖入参考图区域后应直接上传并显示缩略图；拖入非图片文件应忽略，拖动过程中区域应显示高亮提示，放下文件不应导致浏览器打开或替换当前页面。
- 工作台历史图片清理：生图或视频工作台生成内容后，在「我的素材」删除图片、删除画布图片节点、清空画布或删除画布，再次打开对应生成记录时，历史缩略图、结果图片和参考图仍应正常显示；删除生成记录时，其专属本地文件仍应正常清理。
- 视频创作台参考资产：将图片、MP4/MOV 视频或 MP3/WAV 音频拖入任一参考资产区域后，应按文件类型自动上传到对应列表；当前拖入区域应显示高亮提示，原有数量、大小、时长和格式限制应继续生效。
- 画布组装提示词：输入或连接超长提示词后，浮层正文高度不应继续撑大，内容应可在正文区域内滚动查看和编辑，标题及关闭按钮保持可见。
- 画布节点提示词：图片等节点下方的提示词超过输入区域高度后，鼠标悬停在输入区域内滚动应查看提示词内容，不应缩放画布。
- 画布节点提示词回显：单图或多图生成完成后，切换选择生成结果的根节点及任一子节点，下方输入区域都应继续显示生成时的提示词；切换到其他节点再选回来后也不应清空。
- 画布生成配置：连接文本节点后连续点击生成（包含失败重试），组装提示词不应重复追加上游文本；在生图、文本、视频、音频之间切换时，实际请求应始终使用当前面板展示的对应类型模型。
- 画布多图生成：开始生成 N 张图片后应立即创建一个包含 N 个可展开槽位的图片节点，并且来源到结果只保留一条连线；生成期间空槽位应独立显示生成中或失败，任何已有图片内容的槽位都必须始终显示图片，任意图片率先成功后应立即成为主图并展示，不等待其他请求完成；收起状态应最多显示三层紧密错开的背板，避免占用过多画布空间，右上角应显示醒目的「N 张」数量提示；点击数量后，浮动工具条应暂时隐藏，各图片槽位应从当前节点向右上方整齐展开；已成功图片的「设为主图」应常驻显示，并在亮色、深色主题及不同图片背景上保持清晰；点击画布空白处应自动收起并恢复工具条。
- 画布多图主图切换：点击「设为主图」后，节点中心和当前最长边应保持不变，仅按新图片比例调整另一条边；自由变形节点应完全保持现有宽高，画布视口及左下角缩放值不应变化。
- 画布多图失败槽位：包括当前主槽位在内的每个失败槽位都应显示「重试」和「删除」；重试只更新当前槽位，已有成功主图时不得抢占主图；删除只移除当前失败槽位并同步更新图片数量。
- 画布多图尺寸调整：子图展开时开始拖动尺寸控制点，应先收起图片组一次，再正常调整根节点尺寸，不应触发 React 循环更新或应用错误页。
- 画布左侧元素列表：点击元素整行应平滑定位并选中对应节点，自动缩放不得超过 100%；有内容的图片元素应显示预览按钮，点击后打开大图弹窗且不触发画布定位。
- 画布左侧面板：三个页签应等宽且可点击；空画布只显示元素数量和居中的添加提示，不显示无用筛选。添加节点后搜索、类型筛选、列表/缩略图切换与批量选择都应易于操作；无匹配结果可一键清除筛选。资产添加入口、素材卡片操作及提示词列表按钮应在窄面板、明暗主题和键盘操作下清晰可用。
- 画布左侧「资产」中的图片卡片应显示眼睛按钮；点击后可预览原图并关闭，不能误触插入或移除，窄面板与明暗主题下按钮仍应可见。
- 配置与用户偏好：修改渠道、默认模型、生成偏好、提示词来源或 WebDAV 设置后，点击「保存配置」并刷新页面，服务器应保留最终配置；保存失败时不得提示成功，应显示错误并允许重试。
- 生成提示词的文本编号：普通节点或生成配置连接多个文本节点后发起生成，附加在提示词末尾的每段上游文本都应以「【文本1】」「【文本2】」开头并按连接顺序编号，编号与提示词里 `@` 引用及参考内容栏显示的一致；单段文本同样要带编号，图片、视频、音频编号不受影响。
- 局部遮罩编辑：弹窗底部应为「重置」「导出到画布」「立刻生成」；两个按钮都要求已涂抹区域并填写修改要求，「导出到画布」只写入节点和连线不发起请求，结果节点的提示词面板应预填拼好的提示词并可手动生成，「立刻生成」在写入节点后立即生成。涂抹区域并填写修改要求后确认，画布应在原图下方生成一个「遮罩标注」图片节点，内容为原图叠加半透明蓝色标注区域，颜色和透明度应与弹窗里涂抹时看到的一致；结果节点在原图右侧生成，并同时接收来自原图和遮罩标注的两条连线。请求应按普通参考图发送两张图片，提示词按「图片1 / 图片2」编号说明原图和标注区域，不再携带 mask 参数，Gemini 格式渠道也应可用；生成结果只改动标注区域，且不得残留蓝色标注。
- 数据与存储：浏览器本机统计应只读取 `infinite-canvas` 数据库，显示内容估算、站点总占用、浏览器配额与使用率；新增或删除图片、音视频、生成记录后点击刷新，数据应同步变化。非安全 HTTP 环境缺少浏览器容量估算接口时，仍应显示本机数据且配额为不可用。
- 后台运行脚本：执行 `run-background.sh` 后应立即返回；构建期间保持本项目旧预览服务可用，仅在构建成功后切换到新版本，并将 PID 及构建、运行日志写入 `/tmp/infinite-canvas-<UID>/`。
- 本地启动公共脚本：分别执行 `run-all-background.sh status`、`run-all-foreground.sh` 和 `run-background.sh`，确认共用运行时查找逻辑后仍能定位 Bun/Node、以受限权限创建运行目录，并按原行为启动两个服务。
- 群晖 WebDAV 代理：配置地址为 `http://192.168.0.242:5005` 时，浏览器的 `PROPFIND`、`MKCOL`、`GET` 和 `PUT` 只请求同源 `/api/webdav`，不携带 Basic 认证或直连群晖；Bun 服务器应从持久化配置注入凭据并保留路径和请求体，且不能形成开放代理，认证失败也不得弹出浏览器原生登录框。
- 生图工作台资产：使用兼容 OpenAI 接口的 Image2 或 GPT Image 模型生成后，结果应保存到本地，点击「加入我的资产」即使供应商远程地址随后过期也能成功；GPT Image 返回的 Cloudflare R2 图片应通过受限的同源代理下载，浏览器不再出现跨域错误；失败时应显示错误提示，不能静默无响应。
- 服务端配置自动保存：服务器尚无配置文件时应创建默认配置，不从浏览器旧存储恢复；配置页不再显示「上传到服务器」。修改 AI 渠道与 API Key、默认生成偏好、提示词来源与定时设置、WebDAV 配置，以及导入 JSON 后，应自动保存到服务器，刷新、换浏览器或重启 Bun 预览服务后读取一致；快速连续编辑只以最终状态为准，删除渠道后刷新也不应重新出现。服务器读取失败应阻止以浏览器默认值继续运行；写入失败时任意页面都应持续显示错误和「重试」，重试成功后提示消失，不能静默当作已保存。WebDAV 数据快照仍需手动同步。
- 服务端 AI 代理：使用全新浏览器且 `/api/config` 返回的渠道 Key 为空时，生图工作台生成、图片编辑、画布生图、文本请求和模型列表都只能访问同源 `/api/ai/<channelId>/...`；Bun 应从持久化配置注入供应商凭据，拒绝未知渠道和未允许接口，且凭据不得出现在 `/api/config` 响应或浏览器存储中。
- 安全边界：`/api/config`、`/api/ai`、`/api/webdav` 和图片代理路由应拒绝 `192.168.0.0/22` 网段以外的客户端；AI 代理应拒绝 localhost、回环、链路本地、组播及带账号密码的供应商地址。
- WebDAV 手动快照：配置界面不应启用后台自动同步；上传只创建当前工作区快照，不下载或合并远端内容，不上传 AI API Key 或 WebDAV 凭据，保留最近 30 个完整快照。必须由用户手动选择快照导入，同 ID 记录保留本机内容，失败原因持续显示。
- WebDAV 目录检查：同步到群晖已有目录时应先用 `PROPFIND` 确认，不再预先发送 `MKCOL`；多个业务域并发同步应共用一次目录检查，浏览器控制台不再重复出现已处理的 `405 Method Not Allowed`；目录确实缺失时仍应在上传文件前逐级创建。
- WebDAV 并发目录创建：首次同步新快照时，画布、资产、生图和视频四个业务域同时初始化目录，不应因群晖对竞争 `MKCOL` 返回 `403/409/405/423` 而失败；应继续完成四个清单和 `complete.json` 上传。快照 ID 含大写字母、数字、下划线或连字符时，读取快照、导入和自动清理均应正常。
- 模型渠道协议：渠道编辑可选择「火山方舟」并自动填入方舟接口地址；任意名称的生图模型应按方舟 JSON 格式提交参考图，任意名称的视频模型应按方舟任务格式提交和查询，不再依赖模型名包含 `doubao`、`seedream` 或 `seedance`；1080p 不应再因模型名包含 `fast` 被禁用，参考视频应允许最大 200MB、总像素 409600-8295044，并继续校验官方宽高、比例和时长限制。
- WebDAV 画布删除记录：删除画布后上传快照并刷新，再手动导入删除前的快照，已删除画布不应复活。其他设备新建且未删除的画布只有手动导入快照后才出现；明确晚于删除时间的编辑可恢复画布。资产和生成记录的删除合并不在本次范围。
- 数据与存储：在桌面和手机宽度检查服务器与浏览器两栏的层次、数字及展开的技术明细；统计期间页面保持可操作。
- 图片编辑弹窗：遮罩、切图和裁剪连续滚轮缩放时，图片与遮罩应保持同步且不再闪烁、短暂消失或跳动；遮罩画笔圆心应始终固定在鼠标位置，仅直径随缩放变化，缩放后仍可准确涂抹、拖动切分线和调整裁剪框。
- 提示词中心布局：页面标题及提示词总数应居中；连续输入搜索文字时应在停止输入约 300ms 后再查询；桌面端分类与标签应在左侧独立滚动，右侧搜索框下直接展示提示词卡片；标签数量较多时不能继续向下挤压提示词，窄屏下应恢复上下排列且内容不溢出；不再显示「我的提示词」Tab，收藏提示词应直接加入我的资产。
- 提示词详情弹窗：封面和参考图应固定显示在上方，复制及加入资产操作栏固定在底部，只有中间的标签、描述及提示词内容区域可以滚动；弹窗宽高应受视口限制且不超出屏幕。
- 提示词来源：不再内置任何来源，新配置下来源列表为空；添加标准 JSON URL 后应能查看内容，填写非数组 JSON、不可访问地址、私有地址或 HTTP 地址时应显示失败，并继续保留该来源上一次成功缓存的内容。
- 提示词来源界面：来源应以卡片列表展示，启用开关位于左侧，数量、同步状态和上次成功时间作为次级信息显示，查看、拉取及自定义来源编辑/删除操作使用带文字按钮；底部定时拉取区域应保持独立边框布局。
- 画布提示词库：不应再显示「我的提示词」分组；不展开任何公共来源直接搜索其中的提示词，匹配项应自动显示；点击「插入画布」后应创建正文正确且标题保持为提示词标题的文本节点。
- 全站 Agent：新增 `generation_get_status` 工具，画布生成节点可按 `nodeIds` 查询，生图和视频工作台提交后会返回 `taskId` 并可查询排队、运行、成功或失败状态；需验证查询只由当前活动标签页返回。
- 本地 Agent 多标签页隔离：同时打开两个不同画布并连接同一个 Agent，分别聚焦标签页后通过 MCP 读取和修改画布，操作应只落在当前聚焦页面；网页面板发起的整个 Codex turn 应固定操作发起页面，即使中途聚焦另一标签页也不能切换目标；非运行状态关闭当前页面后应回退到最近聚焦且仍连接的页面，运行中关闭发起页面则不得把操作转交其他画布，只有同一页面身份重连后才能继续；其他页面回传同一请求结果应被拒绝。
- 本地 Agent 多标签页会话同步：所有标签页共享同一个站点级 Codex 活跃线程；任一页面发送消息、新建、恢复或删除会话后，其他页面应同步活跃线程和聊天记录；Agent 输出仅显示在事件所属线程，运行中不能新建、恢复、删除或再次发送任务。
- 本地 Agent 运行状态同步：在一个标签页运行较长 Codex 任务，等待某张工具卡显示「工具完成」后再打开或刷新第二个标签页；第二个标签页应立即显示 Codex 正在运行并禁用发送，整轮结束后两个标签页同时恢复；工具卡只显示「工具完成」，整轮结束由「本轮完成」表示。
- 本地 Agent 图片附件落画布：在右侧 Agent 上传参考图并要求基于商品信息创建生图流程，附件应创建为保持原比例的真实图片节点，分析提示词应创建为文本节点，二者都应连接到生成配置节点；刷新页面后参考图仍可显示并参与生成。任务中途切换到其他标签页时，附件只能写入发起任务的标签页；若发起标签页关闭，附件读取应失败且不能落入其他画布。
- Agent 对话滚动：从历史或日志切回对话、恢复其他会话时应自动定位到最新消息；手动向上浏览后应显示与日志完全相同尺寸、位置和样式的居中圆形向下箭头，新消息不强制打断阅读，对话底部不应出现额外留白，点击按钮后平滑回到底部并继续跟随新消息。
- Agent 消息区分：用户消息应在右侧使用透明无气泡排版，AI 回复应在左侧使用无头像的开放式 Markdown 排版；长文本、多张附件、错误消息及浅色/深色主题下均应清晰且不溢出。
- Agent 命令记录：命令执行中应显示运行状态；完成后，同一轮相邻命令应合并为「已执行 N 条命令」折叠行且默认不显示原始命令，单条展开后直接显示完整详情，多条展开后可分别查看命令、输出和退出状态；对话结束或刷新后分组与记录不应消失。
- 跨域提示：生图、视频或音频请求被浏览器跨域策略拦截时，应明确提示需要通过自己的服务转发请求，不再只显示笼统的网络错误。
- 资产图片下载：我的资产中仍可预览的图片，点击「下载图片」应能保存文件；标题含中文、空格或「【】」时应沿用原标题作为文件名，无需改名；从画布刚存入、尚未刷新页面的图片也应能下载。
- 画布视频任务恢复：开始 OpenAI 风格视频生成后，视频节点应保存远端任务 ID。刷新页面后，尚未完成的视频应自动继续查询状态；若查询已停止，可点击「获取任务状态」继续用该任务 ID 拉取，直到生成成功、任务失败或查询请求报错。任务失败后，「重试」应重新发起生成而不是继续查旧任务。

## 图片分辨率尺寸表

选择分辨率和宽高比后，W/H 按下表填写，单位为像素。预设尺寸不受「16 倍数对齐」开关影响；该开关只控制手动输入尺寸时的对齐。最终生成尺寸以所选模型的实际输出为准。

| 宽高比 | 1K | 2K | 4K |
| --- | ---: | ---: | ---: |
| **1:1** | **1024 × 1024** | **2048 × 2048** | **2880 × 2880** |
| **2:3** | 1024 × 1536 | 1360 × 2048 | 2336 × 3520 |
| **3:2** | 1536 × 1024 | 2048 × 1360 | 3520 × 2336 |
| **4:3** | 1024 × 768 | 2048 × 1536 | 3312 × 2480 |
| **3:4** | 768 × 1024 | 1536 × 2048 | 2480 × 3312 |
| **16:9** | 1536 × 864 | 2048 × 1152 | **3840 × 2160** |
| **9:16** | 864 × 1536 | 1152 × 2048 | **2160 × 3840** |
| **21:9** | 2016 × 864 | 2688 × 1152 | **3840 × 1648** |
| **9:21** | 864 × 2016 | 1152 × 2688 | **1648 × 3840** |

待验收：

- 在画布和图像工作台逐项切换 3 档分辨率与 9 种比例，W/H 应与表格一致，重新打开设置后仍选中正确档位；重点检查 1K 的 2:3、16:9、21:9 及对应竖图，以及 4K 的 1:1。
- 所有 4K 预设提交时均不应触发本地总像素或最长边限制；生成和编辑请求、调用脚本应收到所选像素尺寸。
- 分辨率为自动时保留比例选择，比例为自动时禁用 W/H；手动输入 W/H 后，对齐开关仍应按原有方式工作。
- Gemini 请求应带 aspectRatio（所选比例）；分辨率选了 1K / 2K / 4K 时应按尺寸表带上 imageConfig.imageSize，选自动时不带。质量不参与分辨率换算，视频尺寸设置保持原有行为。
- 图像质量可选自动与 5 档（低 / 中 / 高 / 极高 / 最高），请求里的 quality 字段应与所选档位一致，且尺寸不随质量变化。
