# 画布媒体引用与安全垃圾回收规划

成员权限校验、媒体引用表与 GC dry-run 已实现，仍待人工验收。当前阶段不实现实际删除、模板包导入导出、分享或跨工作区复制；自动化结果见[待测试](/zh-CN/docs/progress/pending-test)。

## 当前后端契约

- 数据层为 PostgreSQL + RustFS。工作区数据使用 `GET/PUT /api/data/:domain` 的 revision 条件写入，模板独立使用 `canvas-templates` 域。
- 工作区访问必须具备有效登录会话及 `workspace_members` 成员记录；owner/editor 可写，viewer 只读。工作区列表、摘要、私有提示词及示例图都按真实成员校验，不能靠工作区 ID 或浏览器缓存认领。明确共享的提示词示例图仍允许其他已登录用户读取。
- 创建工作区原子写入归属人与 owner 成员；写入权威数据和媒体索引时锁定工作区行并重查成员角色，记录真实用户 ID。旧版无成员工作区拒绝访问，绑定流程与成员管理界面尚未实现。
- 媒体使用 `PUT/GET/HEAD /api/media/blob/:storageKey`，对象键固定映射为 `media/<workspaceId>/<sha256(storageKey)>`；复制接口在同一工作区内检查读取和写入权限，新副本使用新的 `storageKey`。
- 上传沿用既有 100 MiB 上限，向对象存储明确传入 `ContentLength`。本阶段未新增保留期、扫描频率、超时、重试次数或并发边界。
- `/api/media/agent-attachments` 提供版本化工作区附件清单：成员可读取，owner/editor 可登记、绑定或释放消息引用，viewer 不能修改。服务器在提交清单与引用行前，会核对每个对象属于当前工作区且索引元数据完全匹配。
- 既有 WebDAV 手动快照未加入模板；提示词示例图保存在 PostgreSQL，不属于 RustFS 媒体清单。

## 已实现的媒体引用清单

### 数据结构与事务

- `media_files` 增加 `lifecycle_state`（仅 `staged` / `ready`）及 `last_referenced_at`；没有 `delete_pending` 或删除队列。
- `media_references` 保存工作区、媒体键、所有者类型/ID、源数据域/revision、JSON Pointer 路径、可选 `scan_id` 及观察时间。同一媒体可被多处引用，清单保留各处路径，对象数量去重。
- `media_reference_scans` 保存扫描 ID、工作区、解析器版本、成功/阻断状态、完整 JSON 报告和起止时间。
- 数据域的 CAS 写入、该域引用清单替换、媒体转为 `ready` 在同一数据库事务中提交。冲突返回 409，未知格式或损坏引用返回 422，均保留旧 payload 与清单。
- 引用清单不对媒体索引加外键，因此缺失索引仍可被记录并诊断，而不是静默丢掉引用。删除模板/画布只更新权威 JSON 和引用清单，不删除媒体对象。

### 解析范围

- `canvas`：项目节点、批次结果、显式参考素材及画布内 `chatSessions` 的附件；接受现有 version 0（也允许现有省略 version 的格式）。
- `canvas-templates`：version 1 的模板内容及独立 `template-cover` 所有者；待填写输入占位符不计入对象。
- `assets`：version 0 的图片/视频/音频素材及封面；`image-workbench` / `video-workbench` 读取当前无 version 的 logs 格式。
- 解析已知媒体字段 `storageKey`、`content`、`references`、`dataUrl`、`url`、`coverUrl` 中的规范媒体键；插件显式 `storageKey` 支持合法自定义前缀。远程 URL、`blob:`、`data:`、WebDAV 路径、普通描述和 `template-input:` 不计入对象。
- 对未知域/版本、损坏集合、重复所有者、非法 `storageKey`（含对象和数组）、未知媒体承载字段及根部未归属引用拒绝解析，不当成空数据。
- **独立 `agent-sessions` 已使用 version 1 附件清单**：Agent turn 转发前先上传并保留原图，thread/turn/item 尚未确定时保持 pending 保护，权威历史返回后再绑定。Codex 与 Pi 身份彼此隔离，恢复只为匹配的用户消息补充规范服务器媒体 URL。版本错误、临时 URL、重复消息身份及凭据字段均拒绝；既有 Agent 引擎预览/历史文件不改写，旧缩略图也不会自动补回原图。

## 已实现的 GC dry-run

仅工作区 owner 可调用：

```http
POST /api/media/gc/dry-run
Cookie: <有效登录会话>
x-infinite-canvas-workspace: <所属工作区 ID>
```

1. 在 `REPEATABLE READ READ ONLY` 事务中读取全部已有数据域与媒体索引快照，记录各域 revision。
2. 完成引用抽取；缺少服务器媒体索引会阻断。对应用服务器索引对象逐一 HEAD 并核对大小；`remote_path` 外部快照索引不做 HEAD，也不进入候选。
3. 最终事务取得与权威写入相同的工作区锁，重新核对全部域 revision 与媒体索引快照。
4. 成功时刷新引用清单并存报告；解析、HEAD、大小或并发一致性检查失败时状态为 `blocked`、候选为空，保留上次引用清单。数据库/服务不可用时接口报失败，不返回假成功。
5. 报告固定 `mode: "dry-run"`、`deletionEnabled: false`、`scope: "workspace-prefix-reconciliation"`。只列举精确的 `media/<workspaceId>/` 前缀（逐页处理），对已登记对象做 HEAD 后再次列举并比较。缺失、变化、跨前缀或不完整结果阻断扫描；无索引对象只作为诊断，不会接纳或删除。候选含媒体键、大小、当前生命周期，`eligibleForDeletion` 始终为 `false`。

**这是会持久化报告与引用清单的扫描，不是纯只读请求；但不会删除对象或业务媒体索引。** 上传/复制先创建持久化 active intent，再与媒体索引在同一事务中完成；失败时只记录失败原因，不删除对象。仍 active 的 intent（包括崩溃留下的、不会自动过期的租约）会阻断对账并保留上次清单。失败扫描即使保留部分诊断计数，也不能用于判断可删除对象。

## 尚未解决的边界

- active 上传/复制 intent 提供持久保护，但没有自动过期或不安全的解锁接口；失败请求保留对象和诊断，人工处理另行规划。
- 对账只列举当前工作区精确前缀，不会扫描其他工作区；列举/HEAD/数据库一致性检查失败即阻断。最终列举之后仍可能有远端变化，但当前不执行删除，因此不会冒充已经解决该竞态；未知对象保持无索引诊断，不会被接纳。
- HEAD 与最终提交之间没有对象代际或不可变保证；检查大小和数据库快照不是安全物理删除协议。当前无删除操作，因此不会以此声称已消除将来删除的竞态。
- 尚未专门注入 PostgreSQL 提交失败，或完整验证 Docker 固定运行时及复制清单；专项桌面/移动端回归不能替代这些验证。既有窄屏展开布局、真实音视频/插件与多人并发体验仍待人工验收。

## 后续实际删除的前提（未实现）

1. 继续定义保留期、崩溃遗留 intent 的人工处置、对象代际及删除前 claim 协议；独立 Agent 附件、上传 intent/租约和受限对账已实现，但仍仅报告不删除。
2. 只有完整成功扫描才能提出候选；实际删除须另获授权，并先确认保留期、调度、处理数量及并发等行为边界。
3. **调用对象删除之前**，在事务内核对最新引用、revision、候选代次和媒体代际，原子取得删除 claim。所有保存、上传和复制路径须尊重该 claim，禁止重新引用/覆盖同一删除中的对象；采用不可变对象代际或等价隔离。
4. 只有该隔离在物理删除全过程都成立，才允许使用具备明确权限的服务端执行器删除。删除后数据库确认用于幂等恢复与索引清理，不能用“删完再检查 revision”补救误删。
5. 预先设计对象成功删除但数据库提交失败、删除超时、重复执行及服务重启的恢复流程；失败时不能静默复用旧键或谎报成功。

验收必须包括新引用与删除 claim 的竞争、上传中断、对象代际变化、数据库失败及多工作区隔离。全部继续使用独立 PostgreSQL 数据库/schema、RustFS 桶或前缀及 `.local` 产物目录，不清空业务数据。模板包及分享仍为后续规划，未进入正式功能说明。
