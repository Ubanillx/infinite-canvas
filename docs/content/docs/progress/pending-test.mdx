## Agent Message Queue and Reply Interrupt

- The composer is no longer disabled while Codex or Pi is replying: sending during a run appends the message to the queue, the composer shows "N queued", and the next message is sent automatically when the current reply finishes.
- While a reply runs, Send becomes "Add to queue" and the red Stop button stays available. When the composer has content, an extra "Interrupt and send" action interrupts the current reply, waits for the backend turn to really end, then skips the queue and sends that new input first.
- Stop only interrupts the current reply and pauses automatic draining; queued messages remain. The next manual send resumes automatic draining so nothing fires immediately after a stop.
- Each queued message keeps the text, image attachments, file attachments, canvas references, and Skill captured at send time, so later edits to the composer or a new Skill selection never leak into it; a successful send only clears that message's own Skill selection.
- Switching or creating a conversation clears the queue so messages cannot cross threads. A refresh does not restore the queue, which is expected.
- When a queued message fails to send, its content returns to the composer instead of re-entering the queue, preventing an automatic retry loop; an existing draft in the composer is left untouched.
- If the reply has not stopped within 10 seconds after an interrupt, the log records an interrupt timeout and no new message is forced through, avoiding concurrent-turn conflicts.
