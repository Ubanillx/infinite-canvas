# Docker 部署

## 基于本仓库构建

```bash
git clone https://github.com/Ubanillx/infinite-canvas.git
cd infinite-canvas
git switch dev
docker compose -f docker-compose.local.yml up -d --build --wait --wait-timeout 120
```

默认只绑定 `127.0.0.1:3000`。生产环境请通过宿主机 HTTPS 反向代理访问，配置精确的 `INFINITE_CANVAS_ALLOWED_HOSTS`；局域网直连需要显式设置 `APP_BIND_ADDRESS` 并配置防火墙。镜像构建包含回归测试。

`docker-compose.yml` 用于已加载本仓库镜像的运行部署，`APP_IMAGE` 必须指向本次构建产物（默认 `infinite-canvas:local`，需先构建）。不能使用上游 `ghcr.io/basketikun/...:latest` 来代替这个 dev 分支的服务端实现。

## 服务与数据

容器以 UID/GID 1000 运行 Web 的 Bun/Vite preview 服务和 Node Canvas Agent。Web 保留账号认证、SQLite、工作区数据、媒体、只写密钥配置及 AI/WebDAV/Agent 同源代理；Agent 仅监听容器回环 17371，不单独暴露端口。它不是 Next.js 或 nginx 纯静态应用。

命名卷分别持久化 `/data`、`/home/node/.infinite-canvas` 和 `/home/node/.codex`。AI API Key 保存在服务器，WebDAV 仅手动上传与选择导入快照。不要运行 `down -v` 或 volume prune。备份 SQLite 时需使用一致性备份方法，而非仅复制 WAL 数据库主文件。

旧容器使用 root 目录的卷需要先离线备份并验证 UID、文件权限与配置内绝对路径；不自动修改未知卷。Codex 登录状态不能放入镜像，由管理员首次登录后保存在专用卷中。

## 自动发布

[Jenkins 自动部署](/zh-CN/docs/overview/jenkins) 使用 deploy 分支、GitHub Push Webhook、SSH 严格主机密钥校验、镜像 ID 校验、Compose 健康检查及上一版本恢复。详细配置见仓库 deploy/README.md。

## 统计与文档站

运行参数 `ANALYTICS_GA4_ID` / `ANALYTICS_BAIDU_ID` 默认留空。入口脚本写入运行期 config.js，同时固定 Agent 地址为 `/api/canvas-agent`，不要放入业务密钥。

文档站仍为 `docs/` 下独立的 Next.js 应用，不包含在本应用容器和发布流水线中。容器构建、真实供应商、Codex 登录和生产部署仍需验收。
