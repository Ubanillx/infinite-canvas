# Docker Deployment

## Build this repository

```bash
git clone https://github.com/Ubanillx/infinite-canvas.git
cd infinite-canvas
git switch dev
docker compose -f docker-compose.local.yml up -d --build --wait --wait-timeout 120
```

The default binding is `127.0.0.1:3000`. Use an HTTPS reverse proxy in production and explicitly configure `INFINITE_CANVAS_ALLOWED_HOSTS`. LAN access requires an explicit bind address and firewall policy. Image builds include regression tests.

The main `docker-compose.yml` runs an already loaded image from this fork. Set `APP_IMAGE` to the release image; the default `infinite-canvas:local` must be built first. The upstream published latest image is not a substitute for this dev branch's server implementation.

## Services and storage

The non-root container (UID/GID 1000) supervises a Bun/Vite preview Web service and a Node Canvas Agent. The Web service retains authentication, SQLite, workspace data, media, server-owned credentials and same-origin proxies. The Agent listens only on loopback port 17371. This is not a static nginx or Next.js application.

Named volumes persist `/data`, `/home/node/.infinite-canvas` and `/home/node/.codex`. WebDAV uses manual snapshot upload/import. Do not delete volumes during updates. Back up SQLite consistently, including WAL state. Existing root-owned volumes require an explicit offline migration review of ownership and absolute workspace paths. Codex authentication is provisioned after startup and must never be baked into the image.

## Automatic releases

[Jenkins Deployment](/docs/overview/jenkins) accepts only deploy-branch pushes through a GitHub Webhook, transfers images over pinned SSH and verifies Compose health before recording success. Failed updates attempt to restore the previous image and runtime configuration, not business data. See deploy/README.md in the repository for setup and rollback.

Runtime analytics IDs default to empty; config.js also sets `/api/canvas-agent`. The separate Next.js documentation application in `docs/` is not part of this release pipeline. Real image, provider, Codex and deployment acceptance remain required.
