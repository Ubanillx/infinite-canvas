# Docker Deployment

## Use the published image

```bash
git clone git@github.com:basketikun/infinite-canvas.git
cd infinite-canvas
docker compose up -d
```

Open `http://localhost:3000`.

## Build locally

```bash
docker compose -f docker-compose.local.yml up -d --build
```

## Documentation image

The documentation in `docs/` is a separate Next.js standalone application with server capabilities.

```bash
cd docs
docker compose up -d
```

To build it from the current source:

```bash
cd docs
docker compose -f docker-compose.local.yml up -d --build
```

The application container runs both the Vite preview server and Canvas Agent. The preview server keeps the workspace registry and same-origin WebDAV/Agent proxies available, while the Agent listens only on the container loopback interface. The included Compose volumes persist the workspace registry, Agent conversations, and server configuration across upgrades. AI channels and API keys remain global to the installation and are never copied into workspace snapshots.

Automatic WebDAV sync uploads only the active workspace's snapshots. Remote snapshots are listed and imported only after the user explicitly chooses one in WebDAV settings.

## Optional analytics

No analytics are enabled by default. A deployment can enable GA4, Baidu Analytics, or both at runtime:

| Variable | Description |
| --- | --- |
| `ANALYTICS_GA4_ID` | Google Analytics 4 measurement ID (`G-XXXX`) |
| `ANALYTICS_BAIDU_ID` | Baidu site ID, the hash after `hm.js?` |

```yaml
services:
  app:
    image: ghcr.io/basketikun/infinite-canvas:latest
    ports:
      - "3000:3000"
    environment:
      ANALYTICS_GA4_ID: G-XXXXXXXXXX
      ANALYTICS_BAIDU_ID: e8263761cc5c32f5f7a855b8203b965a
```

SPA route changes automatically report page views to enabled providers. Only configure analytics IDs on sites you control, and do not commit them to the repository.
