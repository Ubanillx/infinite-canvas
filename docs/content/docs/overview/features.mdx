# Features

## Canvas projects

- Create, rename, move, duplicate, delete, import, and export canvas projects, organized with nested folders.
- Store projects per workspace on the server (`/api/data/canvas`); the browser only keeps a local cache.
- Keep viewport, background, nodes, connections, and assistant sessions with each project.
- Save a canvas as a template, create a canvas from a template, or insert a template into the current canvas.

## Infinite canvas

- Pan, zoom, reset the view, select multiple nodes, copy and paste, undo and redo.
- Drag files onto the canvas and use lines, dots, or a blank background.
- Export the entire canvas or selected elements with their resources.

## Nodes and workflows

- Text, image, video, audio, generation-configuration, and group nodes, plus plugin node types shaped as `<pluginId>:<name>`.
- Connect text prompts and reference media to generation nodes.
- Generate or rewrite text, create images, edit images from references, and create videos.
- Preserve original image ratios by default and organize batch results as connected nodes.
- Record prompts, models, dimensions, quality, and references on generated nodes for retries.

## AI generation

- Connect to user-provided AI endpoints through authenticated, server-managed channels.
- Configure multiple channels, fetch or enter model names, and choose default text, image, and video models.
- Support image count, aspect ratio, quality, transparent backgrounds, reasoning effort, and custom invocation scripts.
- Support OpenAI-style video endpoints and Volcengine Ark generation tasks.

## Canvas Agent

- Connect local Codex or Pi through Canvas Agent and MCP without giving a web server direct access to browser state.
- Read the active canvas, selection, nodes, edges, generation status, and apply structured operations.
- Use Codex or Pi from the browser side panel with streaming responses, history, approvals, permissions, diagnostics, and local Skills.
- Isolate active canvases and turns across multiple browser tabs.

See [Codex App Plugin](/docs/overview/codex-app-plugin) for installation and usage.

## Plugin system

Canvas plugins can contribute node types, rendering, inspectors, serialization, migration, toolbar actions, and optional AI generation capabilities. Built-in and local plugins are managed through the canvas UI.

## Prompts and assets

- Add, edit, and remove custom standard JSON sources with independent enablement, manual refresh, and scheduled refresh; the server proxies each fetch.
- Keep the last successful cache when a refresh fails, and show source status with the last success time.
- Search across enabled sources, filter by tags, inspect prompt details, copy prompts, and insert them into the canvas.
- Store reusable images, videos, and text assets per workspace with local browser caches. New assets can be created as text or image in the library; videos are saved from canvas nodes or the workbenches.

No third-party prompt source is bundled any more: a fresh configuration starts with an empty source list, and sources are added on demand as standard JSON URLs.

See [Third-party Prompt Sources](/docs/overview/third-party-prompt-repositories) for the source format and public repositories.

## Configuration and synchronization

- Change AI channels, generation preferences, prompt sources, and WebDAV settings in Settings; every change saves automatically to the server, and a failed save keeps a retryable error.
- Store AI channels and write-only API credentials on the server; the browser receives only redacted configuration.
- Store canvases, assets and records per authenticated workspace, with local browser caches.
- Upload workspace WebDAV snapshots and explicitly select a snapshot to import; existing local records take precedence and canvas deletion markers are retained.

## Current limitations

- The dev deployment includes server-side authentication and workspace data; it requires the Bun/Node service rather than a static frontend alone.
- Server-managed AI and WebDAV requests use same-origin proxies; optional local forwarding does not bypass those boundaries.
- Production Docker static-resource paths still require broader deployment verification.
